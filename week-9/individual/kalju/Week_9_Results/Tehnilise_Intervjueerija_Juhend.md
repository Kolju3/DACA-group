│  ROLL B — Tehniline intervjueerija vaade                         │
│                                                                  │
│  Tehnilise intervjueerija eesmärk on saada aru, kas kandidaadil  │
│  on otsitavad andmeanalüütiku oskused piisaval tasemel olemas.   │
│  Tuleb veenduda:                                                 │
│  • kas kandidaat saab aru, mida ta tegema hakkab;                │
│  • kas kandidaat oskab koodi mõista;                             │
│  • kas kandidaat oskab andmeid mõista;                           │
│  • kas kandidaat oskab andmeid hankida;                          │
│  • kas kandidaat oskab andmeid puhastada;                        │
│  • kas kandidaat oskab andmeid presenteerida.                    │
│                                                                  │
│  Lisaks tuleb hinnata, kas kandidaat suudab teha ühiskoodi.      │
│  Kui kandidaadi kood on väga spetsiifilises vormingus ning       │
│  kasutab ebaregulaarset formaati, ei pruugi ta sobituda teiste   │
│  kodeerijatega samasse meeskonda, sest tema kirjutatud kood ei   │
│  pruugi toimida koos teiste koodi osadega.                       │
│                                                                  │
│  ─────────────────────────────────────────────────────────────── │
│                                                                  │
│  DACA KOGEMUSEST                                                 │
│                                                                  │
│  Oluliseks osutus AI kasutamine koodi kirjutamisel. Tänapäeval   │
│  ei ole enam mõtet ise koodi kirjutada, sest AI teab optimaalseid│
│  funktsioone ja suudab selle kirjutada kiiremini, parema         │
│  formaadiga ning tihti optimaalsemalt. Kuid on ülimalt tähtis,   │
│  et inimene, kes koodi eest vastutab, saab aru koodi toimimise   │
│  mehhanismist. Vastasel korral puudub ülevaade selle üle, mis    │
│  väärtusi kood annab. Kood ei pruugi joosta errorisse, kuid      │
│  toimimismehhanismi tõttu võib jääda mingi asi poolikuks, andes  │
│  väga vale vastuse. Näiteks kui kood, mis küsib Supabasest       │
│  andmeid, ei sisalda pagineerimissüsteemi, annab see tulemuseks  │
│  ainult esimesed tuhat rida — see on aga väga väike osa          │
│  tegelikust andmestikust, kuid ei tekita errorit. Seetõttu on    │
│  väljastatud tulemused valed.                                    │
│                                                                  │
│  ─────────────────────────────────────────────────────────────── │
│                                                                  │
│  ROHELISED LIPUD (tugev kandidaat)                               │
│                                                                  │
│  1. Moduleeritud kood — kood on jagatud loogilisteks             │
│     funktsioonideks või klassideks, igaüks täidab üht kindlat    │
│     ülesannet. See näitab, et kandidaat mõtleb arhitektuurselt   │
│     ja oskab koodi hallata.                                      │
│  2. Dünaamiline kood — kood on kirjutatud nii, et seda saab      │
│     kergesti kohandada erinevate sisendite või tingimustega      │
│     (nt konfiguratsioonifailid, parameetrid). Näitab paindlikkust│
│     ja ettevaatlikkust.                                          │
│  3. GitHubi kasutamine — nähtav regulaarne versioonihaldus       │
│     (commits, branchid, pull request'id) koos asjalike commit    │
│     sõnumitega. See tõestab koostöö- ja versioonihaldusoskust.   │
│                                                                  │
│  ─────────────────────────────────────────────────────────────── │
│                                                                  │
│  PUNASED LIPUD (hoiatusmärk)                                     │
│                                                                  │
│  1. Kommentaarid puuduvad — koodis pole selgitusi, miks või      │
│     kuidas midagi tehakse. See raskendab koodi mõistmist ja      │
│     hooldamist, eriti meeskonnatöös.                             │
│  2. AI tehtud koodi mittemõistmine — kandidaat ei oska           │
│     selgitada, mida tema esitatud kood teeb või miks see nii     │
│     on kirjutatud. See viitab pinnapealsele arusaamale ja        │
│     sõltuvusele tööriistadest, mis võib kaasa tuua eelmainitud   │
│     vigu (nt pagineerimise puudumine).                           │
│                                                                  │
│  ─────────────────────────────────────────────────────────────── │
│                                                                  │
│  MIDA VAADATA VÕI IGNOREERIDA                                    │
│                                                                  │
│  1. Töökogemus: hinda ülekantavaid oskusi teistelt erialadelt    │
│     ja varasemat kokkupuudet sarnaste andmetega — see on         │
│     väärtuslikum kui range tööstaaž.                             │
│  2. Esitluskogemus: vaata, kas kandidaadil on näidata varasemaid │
│     esitlusi ja kas ta suudab oma tulemusi arusaadavalt          │
│     presenteerida — see on oluline andmete edastamisel.          │
│  3. Andme mõistmine: kas kandidaat saab aru, et numbrite taga    │
│     on reaalsed suurused? Kas ta mõistab, millised suurused ja   │
│     suhted loevad ning mis mitte?                                │
│  4. Programmeerimiskeel: ei ole väga tähtis, et inimesel oleks   │
│     just konkreetne keeleoskus — olulisem on võimekus koodi      │
│     loogikat mõista ja ühest keelest teise üle minna.            │
│  5. AI kasutamise võimekus: hinda, kas kandidaat oskab AI-d      │
│     tõhusalt kasutada, sest see vähendab aega mehhaniseeritud    │
│     tööle.                                                       │
│                                                                  │

│  KOKKUVÕTE: Tehniline intervjueerija peaks keskenduma koodi      │
│  loetavusele, struktuurile, dokumentatsioonile ja kandidaadi     │
│  võimekusele oma lahendusi selgitada. Rohelised lipud (nt        │
│  moduleeritud ja dünaamiline kood, hea GitHubi kasutus)          │
│  ennustavad head meeskonnatööd ja pikemaajalist edu. Punased     │
│  lipud (nt kommentaaride puudumine ja AI-koodi mittemõistmine)   │
│  on märgid, mis vajavad täiendavat kontrolli. Samuti tuleb       │
│  hinnata ülekantavaid oskusi ja andmete mõistmist, mitte ainult  │
│  konkreetse keele või töökogemuse formaalset vastavust.          │
